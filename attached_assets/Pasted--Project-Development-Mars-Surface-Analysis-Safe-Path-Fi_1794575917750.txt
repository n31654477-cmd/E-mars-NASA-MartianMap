# Project Development: Mars Surface Analysis & Safe Path Finder

I want you to develop a complete web application that generates an interactive 2D map of Mars and identifies dangerous and relatively safe regions using the scientific data provided through the connected Google Drive sources.

The application must use:

- **Backend:** C# with ASP.NET Core Web API.
- **Frontend:** HTML, CSS, and JavaScript.
- **Map visualization:** An appropriate 2D mapping library capable of displaying Mars geographic data and custom GIS layers.

The Google Drive integration is already authorized. Use the previously extracted information from the documents, PDFs, spreadsheets, GIS files, and databases.

I will also provide an existing source-code prototype of the application. This prototype is extremely important and must be treated as the primary technical reference for the application's functionality and algorithms.

Only implement criteria supported by the available scientific information.

Do not invent measurements, values, thresholds, or scientific relationships.

Preserve original measurements, units, coordinate reference systems, and source references.

### Porting the prototype

The new application will have an ASP.NET Core backend written in C#.

If the prototype uses C#, preserve its algorithm implementations and adapt only the surrounding application architecture where necessary.

If any part needs to be translated into another language or adapted to a different data representation, reproduce its original behavior and logic faithfully.

Changes required for integration must not silently change algorithm behavior.

If an implementation detail cannot be preserved exactly, explain why and ask for approval before changing it.

- Radiation.
- Slope.
- Terrain characteristics.
- Other available scientific measurements.

Implement appropriate visualizations:

- Color-coded danger levels.
- Individual GIS overlays for different danger criteria.

- A legend explaining each color.
- Detailed information panels for selected locations.

If a source does not establish a reliable threshold, identify that limitation instead of inventing one.

Clearly distinguish between measured, derived, and estimated values.

This section is especially important.

The new scientific datasets must supply the environmental information used by the existing prototype's grid and pathfinding system.

The objective is to integrate real Mars data into the prototype's existing computational model, not to create an entirely different pathfinding system.

For example:

- Associate relevant environmental measurements with their corresponding cells.
- Calculate danger or safety values using scientifically justified methods.
- Identify blocked or impassable regions using supported criteria.
- Supply the resulting cell information to the existing pathfinding algorithms.

Preserve the prototype's algorithm implementations.

If the scientific datasets require additional preprocessing, coordinate transformations, normalization, or data aggregation, perform those operations before passing the data to the algorithms.

Do not change the algorithms simply to accommodate a new dataset.

If the prototype's existing data model cannot represent an important scientific measurement, extend the data model without changing the existing algorithm's behavior unless I explicitly approve such a change.
